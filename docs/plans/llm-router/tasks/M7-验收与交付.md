## 本阶段目标

对照 A1–A11 逐项自证，产出可复现的验证脚本与结果表；补齐文档。

**评分看的是论证完整性，不是"全绿"。** 每一条取舍都要写进报告——软限额、Anthropic 推理 token 不可拆、吊销生效 ≤15s、translate 未交付，这些如实写出来比藏起来更有说服力。

## 本阶段的硬约束（既定决策，不要自行改动方向）

- 每项验收给出四段：**判定口径 → 验证方法 → 命令/测试 → 已知取舍**。
- 验证一律打**本地假上游**，不打真供应商——否则"逐字节一致"无法判定，也不可复现。
- A11 的核心证据是**堆快照对照实验**：router 进程能 grep 到明文（设计如此），web/control-worker 进程为空。这比任何代码审查都有力。

## 易踩坑

- A5 要先设 `OPENRUSH_V1_EVENTS_ENABLED=true` 才能看到 `data-openrush-usage`（默认关闭）。
- A7 要给**两组**数据：NOTIFY 正常时的实测，和**故意断开 LISTEN** 后靠轮询兜底的实测。只给一组证明不了"上界确定"。
- A2 要**分别报告 TTFB 附加延迟与总耗时附加延迟**——网关的价值就在于 TTFB 几乎不受影响。
- 如果 T4.7（translate）裁掉了，在 F2 一栏如实写"双协议对外面已交付，跨协议翻译列为后续"，不要含糊带过。
