## 本阶段目标

把网关接进 open-rush 的实际链路：control-worker 签发 per-run 令牌 → 注入沙箱 env → agent-worker 不再持有真 key → run 收敛时聚合用量并吊销令牌。

顺带修一条既有断链：`runs.model_id` / `agents.model` 三列存在但从不被读（R1 §2.6）。

## 本阶段的硬约束（既定决策，不要自行改动方向）

- **`llmAccess` 是 `RunOrchestrator` 的可选依赖**。未装配时行为与改造前完全一致——这是灰度与回滚开关，不要做成必选。
- env 合并顺序固定为 `{...vaultEnv, ...grant.env}`：**router 后写、优先级更高**。这条要写进代码注释和 Spec，否则未来 Vault 真接线时会打架。
- 令牌吊销放在 `finally`，**成功和失败路径都要走到**。
- `agent-worker` 里用**显式 `undefined` 抹除**密钥键，而不是"不设置就没有"——见下面的坑。

## 易踩坑

- ⚠️ **最容易踩的坑（R3 §4.2.1）**：`grant.env` 有两条到达 Claude Code 子进程的路径。dev 模式下 `LocalDevSandboxProvider.create()` **完全忽略 `options`**，所以只改 `sandboxProvider.create({env})` 会看到"网关根本没被调用、还在直连"。**必须同时把 `sandboxEnv` 传给 `agentBridge.sendPrompt`**。
- 同样在 dev 下：`apps/agent-worker/.env.local` 里的 `ANTHROPIC_BASE_URL` / `ANTHROPIC_API_KEY` **必须清空**，否则会覆盖掉注入的网关地址。
- ⚠️ **依赖版本漂移（R1 §2.8）**：锁定的 `ai-sdk-provider-claude-code@3.4.4` 子进程 env 白名单**不含** `ANTHROPIC_*`；但 3.6.0+ 新增了 `ANTHROPIC_*`/`AWS_*` 前缀继承。所以要**显式置 `undefined`**，让这条不变量不随升级漂移，并配回归测试。
- `data-openrush-usage` 走 `appendAssignSeq`，受 `OPENRUSH_V1_EVENTS_ENABLED` 控制且**默认关闭**（只认字面量 `"true"`）。验收时要显式开启。注意：`llm_calls` 的写入**不依赖**这个 flag。
- 依赖方向：control-plane 要用 `mintRouterToken`/`hashRouterToken`。是让 control-plane 依赖 llm-router，还是把这两个纯函数下沉到 contracts？**Sparring 时定夺**，不要自己拍。

## 阶段完成判定

## 任务卡

#### T6.1 `LlmAccessService`
- **产出**：`packages/control-plane/src/llm/{llm-access-service.ts,router-token-store.ts,drizzle-router-token-store.ts}`；`control-plane/src/index.ts` 导出
- **要点**：control-plane 的 `package.json` 加 `"@open-rush/llm-router": "workspace:*"`（只为 `mintRouterToken`/`hashRouterToken`），或把这两个纯函数下沉到 `packages/contracts` 避免反向依赖 —— **Sparring 时定夺依赖方向**
- **验收**：签发返回明文且库里只有 hash；吊销幂等；过期时间计算；`aggregateUsage` 的 SUM 正确（含无记录返回 null）
- **依赖**：T1.1, T4.2

#### T6.2 `RunOrchestrator` 接线
- **产出**：`run-orchestrator.ts` 改动（见 C8 §7.17）+ `agent-executor.ts` / `agent-config.ts` 补 model（见 C8 §7.18）+ `drizzle-agent-config-store.ts` 读出 `agents.model`
- **要点**：`llmAccess` 为**可选依赖**——未装配时行为与改造前完全一致，这是灰度开关
- **验收**：
  - Red Test 先行：断言 `sendPrompt` 收到 `modelId`（修复 2.6 的断链）
  - 装配 llmAccess 时：sandbox env 含 `ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN`/`ANTHROPIC_MODEL`
  - `finally` 里必定调 revoke（成功路径 + 抛错路径各一例）
  - 未装配 llmAccess 时不改变任何既有行为（回归）
- **依赖**：T6.1

#### T6.3 `agent-worker` 密钥边界
- **产出**：`apps/agent-worker/src/server.ts` 改动（见 C8 §7.16）+ `.env.example` 更新
- **验收**（**A11 回归测试**）：mock `claudeCode`，断言传入的 `env` 对象中 `ANTHROPIC_API_KEY`/`AWS_*` 为 `undefined`，**即使 `process.env` 里设了这些值**
- **依赖**：无（可与 T6.2 并行）

#### T6.4 control-worker 装配

- **要点**：`LLM_ROUTER_BASE_URL` 未设置时**不装配** llmAccess（保持旧行为），并打一条 warn
- **验收**：环境变量存在/不存在两条路径
- **依赖**：T6.1, T6.2

#### T6.5 日志清洗与审计 ⇉
