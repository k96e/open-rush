**自审发现并当场修掉的 3 条**：

1. **批内不去重会让整批被丢**——`ON CONFLICT DO UPDATE` 不允许同一冲突目标在一条语句里被命中两次，而一批 100 条调用几乎必然落在同一个 (作用域, 窗口) 桶。修法：`aggregateBudgetDeltas` 先在内存里按桶聚合，一批只写十几行（并有一条 100 条同项目调用只写 3 行累计器的用例钉死）。
2. **`RedisRateLimiter.tryAcquire` 只回 true/false，给不出 `Retry-After`**，而 R5 §6.2 要求限流的秒数取「滑动窗口剩余时间」。修法：拒绝路径上多跑一段 `ZRANGE … WITHSCORES` 读最老成员的分数（只在拒绝时发生），读不到就用兜底值；同时给 `routerErrorResponse` 加了「429 缺省 60s」的兜底，堵住调用点漏传。
3. **`llm_budgets.window` 是 PostgreSQL 保留字**，PGlite 建表 DDL 不加引号直接语法错误。真 migration 里 drizzle 生成的是 `"window"`，测试库的手写 DDL 漏了引号——修掉后才对得上「DDL 逐字对齐 `0012_llm_router.sql`」这条约定。
