## 本阶段目标

把方向**写死在仓库里**，再动一行实现代码。产出两样东西：`specs/llm-router.md`（设计决策的 source of truth）与 `packages/contracts/src/v1/llm-router.ts`（类型契约）。

本课题属于 `AGENTS.md` 定义的 **Large 变更**（新模块 + 跨多 package），流程是 `Plan → Sparring Review → Spec → Sparring → 实现`。计划书本身是 Plan，本阶段补的是 Spec。

## 本阶段的硬约束（既定决策，不要自行改动方向）

- **D1–D12 是既定结论**（见 R2）。Spec 的作用是**记录**这些选择及理由，不是重新开一轮讨论。若确实要推翻某条决策，先改计划书、重新 Sparring，再改 Spec。
- 契约用 **zod v3** API（仓库锁定 `zod@3.25.76`）：写 `z.string().uuid()` 而不是 v4 的 `z.uuid()`。
- Spec 必须写明与 `specs/credential-proxy.md` 的关系——两者互补不冲突，不写清楚后来者会误判。

## 易踩坑

- **跳过 Sparring 直接写代码 = 违反 `AGENTS.md` 铁律**，无例外。
- 往 `ServiceTokenScope` 加 `llm:read`/`llm:write` 后，`packages/contracts/src/v1/__tests__/common.test.ts` 里已有的枚举断言会红——**必须同步更新**，不要注释掉。
- `llmCredentialSchema` 的字段列表是 A11 的第一道闸门：结构上就不能有 `sealedValue` / `value`。单测要显式断言这一点。
