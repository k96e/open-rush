## 本阶段目标

建 7 张 `llm_*` 表 + migration `0012_llm_router.sql`，并给 `@open-rush/db` 加一个 LISTEN/NOTIFY 的独立连接工厂。

这一层做完，后面所有 store 都有地方落。

## 本阶段的硬约束（既定决策，不要自行改动方向）

- 遵循 `specs/migration-policy.md`：**schema 与 migration 必须在同一个 commit**，CI 会卡。
- 前向迁移，不写 down migration。
- 所有新表统一 `llm_` 前缀，barrel 从 `packages/db/src/schema/index.ts` 导出。

## 易踩坑

- **`drizzle.config.ts` 的 `schema` 指向 `./dist/index.js`，不是源码。** 忘了先 build 就 `drizzle-kit generate` 会产出空 migration。用仓库脚本 `pnpm --filter @open-rush/db db:generate`，它会自动先 tsup。
- `llm_catalog_state` 是单行表，**种子 INSERT 必须手写进 migration 末尾**，drizzle 不会替你生成：
  `INSERT INTO "llm_catalog_state" ("id","version") VALUES (1,0) ON CONFLICT ("id") DO NOTHING;`
- `numeric` 列在 drizzle 里映射成 **string** 而不是 number，写测试和 `computeCostUsd` 时注意。
- LISTEN 需要**独占连接**，不能复用 `getDbClient()` 的连接池——所以 T1.2 是新建 `postgres(url,{max:1})`，不是改现有 client。
